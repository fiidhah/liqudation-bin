FOUNDATIONAL PRINCIPLES
1. What is Forensic Data Acquisition?

The Golden Rule of Forensics

  • Digital evidence is fragile and changes easily.
  • Booting Windows normally overwrites logs and timestamps.
  • Golden Rule: Never alter the original evidence!
  • We must clone an exact duplicate and only examine the copy.

Why Use a Linux Live USB?

  • Runs 100% inside RAM without touching the hard drive.
  • Bypasses the suspect OS and any hidden malware.
  • Prevents automatic file updates or auto-wipe triggers.
  • Allows mounting drives in strict Read-Only mode.

TOOLKIT & SETUP
2. Requirements & Preparation

Hardware Tools

  • Live USB: Forensic OS like CAINE or Kali.
  • Target Drive: Suspect's PC or hard drive.
  • Destination Drive: Empty external drive (larger size).
  • Write-Blocker: Physically stops writes.

Software Tools

  • Guymager: Fast visual GUI tool.
  • dc3dd / dd: Command-line disk cloner.
  • Hashing: md5sum and sha256sum.

Documentation

  • Case number & Officer name.
  • Drive Model & Serial Number.
  • Date, time, and location logs.
  • Chain of Custody form.
🗣️ What to say:

STEP-BY-STEP WORKFLOW
3. Booting From the Live USB
Step 1: Plug In • Insert the prepared Linux Live USB into the suspect machine while it is powered OFF.
Step 2: Access Boot Menu • Power on and immediately press F12 (or F2 / Del) to open BIOS/UEFI Boot Menu.
Step 3: Select USB • Choose the USB drive so the computer boots from USB and ignores the internal Windows drive.
Step 4: Forensic Mode • Start Linux in Forensic Mode. This ensures connected drives are NOT auto-mounted.
🗣️ What to say:
"To boot safely, we plug in the USB while the PC is off, press the boot key like F12, and boot directly into Linux Forensic Mode. This ensures the internal hard drive remains sleeping and unmounted."
CRITICAL IDENTIFICATION
4. Identifying the Evidence Drive

Identifying Drives in Linux

  • In Linux, drives are called /dev/sda, /dev/sdb, etc.
  • Always check device SIZE and MODEL:
    • Source (Suspect): 500GB SSD
    • Destination (Backup): 1TB External Drive
  • Danger: Never confuse source and destination, or you could overwrite evidence!

Commands to Run

lsblk
Lists all disks, sizes, and partition names
sudo fdisk -l
Displays detailed sector counts and partition tables
hdparm -r1 /dev/sda
Enforces software write-protection (read-only)
🗣️ What to say:
"Next, we identify which drive is the suspect's drive using the lsblk command. We match the storage capacity and brand name. We double-check so we never accidentally write over the original evidence."
IMAGE CREATION
5. Creating the Forensic Image

1. Software Used

  • Guymager: Clean graphical interface; easy to use.
  • dc3dd: Forensic version of dd with progress monitoring.
  • Makes a bit-by-bit exact copy of every sector.

2. Image Formats

  • E01 (Expert Witness): Gold standard in forensics. Compresses empty sectors and embeds case metadata.
  • RAW / DD: Simple raw byte clone.

3. Safe Execution

  • Select Source: Evidence Drive.
  • Select Destination: External Storage.
  • Start imaging and never interrupt power or cables.
🗣️ What to say:
"Now we create the forensic image using Guymager. We choose the E01 format because it stores case info and compresses unused space. The software reads every single 0 and 1 from the suspect drive and saves it onto our external drive."
COURTROOM INTEGRITY
6. Verification & Documentation

Cryptographic Hashing

  • A Hash is a unique digital fingerprint (SHA-256 / MD5).
  • Even a 1-bit change creates a completely different hash.
  • Calculate Hash of Source Drive.
  • Calculate Hash of Acquired Image.
  • If Hash A == Hash B: 100% legal proof the copy is identical!

Chain of Custody

  • Document tool name, exact version, date, and timestamps.
  • Record both hash values in the official case report.
  • Original drive is locked in an evidence locker.
  • Investigators only analyze the forensic copy.
🗣️ What to say:
"Finally, we verify integrity using cryptographic hashes like SHA-256. If the hash of the original drive matches the hash of our image file, it mathematically proves in court that the copy is authentic and uncorrupted."
SUMMARY & CONCLUSION
Summary of 5 Simple Steps
1. Prepare: Live USB + external storage + documentation.
2. Boot: Boot from USB directly into RAM (Windows stays asleep).
3. Identify: Use lsblk to verify source drive.
4. Image: Clone to E01 format using Guymager.
5. Verify: Match SHA-256 hash values to prove 100% integrity.
